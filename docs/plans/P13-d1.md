# P13 — Pindah database ke Cloudflare D1 (D051)

## Latar
Neon Free kehabisan kuota compute (100 CU-jam/bulan) karena cron worker Cloudflare (D050) membuat compute Neon menyala 24 jam. Semua query ditolak (`53000 exceeded the quota`). User memilih pindah ke D1 (SQLite milik Cloudflare), dengan lapisan adapter supaya ganti database cukup di driver.

## Keputusan desain
- **Satu dialek: SQLite, di mana pun.** Satu skema (`drizzle-orm/sqlite-core`) dan satu kode query untuk semua lingkungan. Yang berbeda hanya driver (adapter) di `packages/db/src/client.ts`:
  - Cloudflare Workers → `drizzle-orm/d1`, binding `DB` (dari scope request OpenNext / `apps/worker/src/cf.ts`).
  - Lokal (Bun/Node: `bun run dev`, worker, MCP, script, test) → `drizzle-orm/libsql` + `@libsql/client` dengan file `DATABASE_URL=file:.data/<nama>.db`.
- **Tidak ada lagi Postgres/Docker** untuk database. `docker-compose.yml` dihapus, dan `bun run setup`/`dev` membuat file SQLite + migrasi.
- **Tipe kolom:**
  - `timestamp` → `integer` mode `timestamp_ms`.
  - `jsonb` → `text` mode `json`.
  - `boolean` → `integer` mode `boolean`.
  - `serial` → `integer` primary key autoincrement.
  - u64 → tipe kustom `u64` (INTEGER ↔ `bigint`, ditolak bila > 2^53−1, karena API D1 tidak mendukung BigInt dan integer hanya aman sampai 2^53).
- **Tanpa transaksi interaktif.** Drizzle-D1 `transaction()` mengirim `BEGIN`, dan D1 menolaknya. Penggantinya:
  - `db.batch([...])`, yang atomik di D1 dan libSQL;
  - statement tunggal bersyarat (`INSERT … SELECT … WHERE (SELECT count(*)) < N`);
  - klaim optimistis (`UPDATE … WHERE next_run_at = <lama> RETURNING`) untuk autopilot, menggantikan `FOR UPDATE SKIP LOCKED`;
  - counter like/comment dihitung ulang dari tabel sumber dalam batch yang sama.
- **SQL khusus Postgres diganti:**
  - `DISTINCT ON` → `ROW_NUMBER() OVER (PARTITION BY …)`;
  - `ilike` → `like` (case-insensitive ASCII di SQLite);
  - `greatest` → `max()`;
  - `date_trunc('day')` → pembagian integer ms;
  - cast `::timestamptz`/`::int` dihapus;
  - advisory lock dihapus.
- **Migrasi:** `drizzle-kit generate` (dialect sqlite) menghasilkan `packages/db/drizzle/0000_*.sql` baru; migrasi Postgres lama dihapus.
  - Lokal: migrator libSQL (`migrateLocal`).
  - D1: `wrangler d1 migrations apply stockbreak --remote` di build command Workers Builds (`migrations_dir` di `apps/web/wrangler.jsonc`).
- **Data produksi:** D1 mulai kosong. Indexer mengisi ulang index/posisi/event dari chain (resync). Histori harga/snapshot mulai dari nol; data sosial lama hilang (Neon terkunci kuota).
- **Rahasia:** D1 diakses lewat binding (ID database bukan kredensial). Tidak ada URL/password DB di repo.

## Langkah
1. Dependensi: `@libsql/client` (+ hapus `postgres`) di `packages/db`.
2. Skema sqlite-core + tipe `u64`; generate migrasi SQLite.
3. `client.ts`: adapter D1/libSQL, `migrateLocal`, `closeDb`.
4. Port `queries.ts`, `social.ts`, `autopilot.ts`, `agent-keys.ts` (tanpa `transaction`/SQL Postgres).
5. Aplikasi: `wrangler.jsonc` web + worker (binding `DB`, hapus Hyperdrive), `next.config` (`serverExternalPackages`), env default `DATABASE_URL`.
6. Script: `setup`, `dev`, `db-reset`, `seed`, `gate-worker`, `verify-devnet`, `devnet-db`, `db-remote` (diganti/diperkecil), `.env.example`, hapus `docker-compose.yml`.
7. Test: `packages/db` (file `:memory:`/temp), `apps/mcp`, `apps/worker`.
8. Cloudflare: buat D1 `stockbreak`, ID ke `wrangler.jsonc`, ganti build command (migrasi D1), hapus build secret Neon.
9. Docs: PLAN §3/§7.3, DEPLOY Opsi C, DECISIONS D051, STATUS (`contract:`), VERSIONS.

## Gate
- `bun run typecheck`, `bun run lint`, `bun run test:ts` hijau (DB test di SQLite).
- `bun run dev` localnet berjalan (worker menulis ke SQLite, web membaca).
- Salinan build OpenNext + worker lolos `wrangler dev` lokal dengan D1 lokal.
- Produksi: `bun run check:public -- https://stockbreak.fun` → PASS 11/11.
